# ADR-0006 控制台：不引图表库，admin token 放在浏览器

- 状态：已采纳（开发 / 演示期方案）
- 日期：2026-11

## 背景

控制台的目标是让「成本 / 缓存 / 降级 / 耗时」这四个抽象概念变成一屏能看的东西。
作品集里它承担的是**产品判断力**的证据，不是前端工程能力的炫技。

## 决策

### 1. 不引入图表库

7 根柱子的柱状图用 `div` + CSS 高度实现，没有 Recharts / ECharts / Chart.js。

- 省下 100KB+ 依赖和一个 SSR 兼容问题（图表库大多要 `dynamic(ssr:false)`）。
- 代价：没有坐标轴、tooltip、缩放。当前信息量下不值得为它们付依赖成本。
- 何时该换：一旦需要多序列对比、时间范围缩放、或者 >30 个数据点，手写 SVG 的边际成本
  就超过引库了。这个门槛写在代码注释里，避免下一个人重新纠结。

### 2. admin token 直接进浏览器（`NEXT_PUBLIC_AIGATE_ADMIN_TOKEN`）

- 现状：MVP 没有登录体系，控制台和网关同机部署。
- 风险：token 会进前端 bundle，任何能打开页面的人都拿到管理权限。
- 为什么不现在做：真正的后台登录 = SSO + 服务端会话 + CSRF + 分租户授权，至少两周，
  而它不产生任何「网关能力」上的新证据。
- **所以它被写进 README 的「已知限制」，而不是藏在代码里。** 面试被问到就答：
  「我知道这是错的，我把它当已知缺陷列出来了，生产化清单第一条就是它。」

### 3. 聚合在 Python 里算，不在 SQL 里算

`overview` 把窗口内的 usage_records 读出来在内存聚合。

- 万级行：微秒级，且不依赖 SQLite/PostgreSQL 的日期函数差异（`strftime` vs `to_char`）。
- 代价：百万级会慢。届时正确的做法是**物化日表**（每天一行，跑批更新），而不是把
  `GROUP BY` 硬塞进请求路径——聚合口径会变，物化表才是能长期演进的地方。

### 4. 截图用合成数据，并在文档里说清楚

`scripts/seed_demo.py` 生成 7 天的模拟流量（含周末低谷、4% 错误率、30% 缓存命中）。

- 目的：让图表有形状，不至于空着。
- 风险：看起来像真实业务量。
- 处置：README 与脚本 docstring 都明确写「synthetic / 合成数据」，简历里也不拿这些数字
  当业务成果。**演示数据的价值是证明系统能算，不是证明系统跑了很多量。**

## 后果

生产化清单（按优先级）：

1. 控制台改服务端会话 + SSO，token 不再下发浏览器
2. 聚合落物化日表，支持按租户切片
3. 审计日志：谁在控制台上签发/吊销了 Key
4. 图表按需引库（超过 30 个数据点或需要多序列时）
