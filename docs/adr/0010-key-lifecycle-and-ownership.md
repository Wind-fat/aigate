# ADR 0010 · Key 的归属、过期与自助签发

## 背景

key 是这套系统里最像"凭证"的东西：它一条就能花掉一个项目的全部预算，泄露一次就要写事故报告。
但最初的实现只有 `name / prefix / hash / status`——**谁签的、干什么用、什么时候作废，一个都答不出来**。

同时有两个真实缺陷：

1. `POST /admin/v1/keys` 与 `POST /admin/v1/keys/{id}/revoke` **没有任何鉴权依赖**。
   任何登录会话（包括只读的开发者账号）都能给任意项目签发 key，也能吊销任意 key。
   接口返回 201，看起来一切正常。
2. 开发者想用自己的项目，必须先找 owner 签一把、再通过聊天把明文发过去。
   这条路径把 key 永久留在了聊天记录里。

## 决定

### 1. key 是一等公民，带归属与生命周期

`api_keys` 增加：`created_by / created_by_email / description / environment / expires_at /
revoked_reason / revoked_by`。

- **归属存邮箱也存 id**：账号删了之后还要能回答"这把是谁签的"，只存 id 就变成死胡同。
- **`environment` 不是装饰**：`prod` 强制要求 `expires_in_days`。没有过期时间的生产 key，
  不会有人主动去轮换——它会一直活到泄露那天。
- **吊销必须给理由**（可为空但会显示在列表）：三个月后问"这把为什么停了"，空答案只能靠猜。

### 2. 两种签发权限，边界在"自己的项目"

| 角色 | 能给谁签 | 能吊销谁 |
|---|---|---|
| owner / admin（`keys:write`） | 任意项目 | 任意 key |
| viewer（`keys:own`） | 仅 `project_scope` 内的项目 | 仅自己签的 key |
| finance | 不能签 | 不能吊销 |

规则落在**端点内部**，不是靠界面隐藏按钮。`get_actor` 里那条"非 GET 一律需要 admin"的粗暴规则
为 `/admin/v1/keys` 开了口子——否则开发者永远走不到细粒度检查就被 403 拦掉。
开这个口子是有代价的（多一处例外），代价换来的是"不再有人把 key 粘进聊天"。

### 3. 过期在数据面校验，错误码指向动作

`get_principal` 读到 `expires_at` 已过 → `401 gateway.key_expired`，而不是笼统的 `invalid_key`。
两者都是 401，但下一步动作完全不同：前者去控制台换一把，后者去查拼写。

### 4. 成员可编辑（否则上面的规则修不回来）

原先只能创建成员时指定 `project_scope`，创建后无法修改。仓库里因此躺着两个
"scope 为空、登录后什么都看不到、也签不出 key"的开发者账号——**管理员在界面上无法修复的状态，
就是一个坏掉的产品**。新增 `PUT /console/v1/users/{id}`：角色、可见项目、状态、重置密码。

三条护栏：只有 owner 能改 owner；不能改自己的角色/停用自己（一把钥匙锁门里）；
viewer 至少一个项目，且项目 id 必须在库里存在（拼错的 id 存进 scope 的效果是静默的"什么都看不到"）。

## 后果

- 好处：签出去的东西可追溯、可轮换、泄露时能自助止血；开发者不再需要 owner 转发凭证明文。
- 代价：`api_keys` 多 7 列，签发多 3 个必填判断；控制台多一个编辑面板。
- 不做：key 的自动过期轮换任务（当前靠列表上的"14 天内过期"提示 + 人工）。真正需要时
  加一个定时任务扫描 `expires_at` 并把结果推到告警渠道即可，不需要改表。
